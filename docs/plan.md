# Odolog — план разработки

## Контекст

Замена связки Telegram + Google Sheets для учёта пробега и расхода топлива.
Единая сущность Entry с полем `type`: показание одометра (`odometer`) или заправка (`fuel`).

---

## Стек

| Слой | Технология |
|------|------------|
| Frontend | React + Vite + TypeScript + Tailwind CSS |
| Offline DB | Dexie.js (IndexedDB) |
| Backend | Node.js + Express + SQLite (better-sqlite3), отдаёт и API, и статику фронта |
| Auth | JWT Bearer |
| PWA | vite-plugin-pwa |

## Схема данных

Одна таблица `entries` — discriminated union по `type`.
Заправка = надмножество показания одометра, поэтому показания живут на одном таймлайне.

```ts
// vehicles
{ id: string, name: string }

// entries — discriminated union по type
type EntryBase = {
  id: string
  vehicleId: string
  measuredAt: number   // момент измерения, задаёт пользователь
  odometer: number
  createdAt: number    // момент создания строки, системный, иммутабельный
  updatedAt: number
  deletedAt: number | null
  synced: boolean
}
type OdometerEntry = EntryBase & { type: 'odometer' }
type FuelEntry     = EntryBase & { type: 'fuel'; liters: number; totalCost: number }
type Entry = OdometerEntry | FuelEntry
```

Индекс Dexie: `id, vehicleId, type, measuredAt, synced, deletedAt`.

- `id` — nanoid, генерируется на клиенте (записи — 21 симв, машины — 6 симв для URL)
- `measuredAt` — epoch ms, момент измерения; задаёт пользователь (дата + время, точность до минуты), по умолчанию «сейчас», редактируемый; **по нему строится порядок и считается пробег**. Заменяет прежний `date`
- `createdAt` — epoch ms, момент создания строки; системный, иммутабельный; нужен для тай-брейка при равном `measuredAt` и для аудита (видно записи, внесённые задним числом)
- `synced` — флаг локальной синхронизации
- `updatedAt` — timestamp (ms), при конфликте побеждает большее значение
- `deletedAt` — timestamp (ms) мягкого удаления, `null` если запись активна

---

## Синхронизация

Двусторонняя, сервер — источник истины.

1. Push: отправляем все записи где `synced = false`
2. Pull: тянем с сервера все записи новее `lastSyncAt`
3. Конфликт по одному `id`: побеждает запись с бо́льшим `updatedAt`
4. Авто-sync при появлении сети + кнопка ручного sync

## Архитектура

### Frontend — Feature-Sliced Design (FSD)
```
src/
  app/        # провайдеры, роутинг, глобальные стили
  pages/      # страницы
  widgets/    # составные блоки UI
  features/   # фичи (add-odometer-entry, add-fuel-entry, sync)
  entities/   # сущности (vehicle, entry)
  shared/     # lib (db, api-client), ui (компоненты), types
```

### Backend — Onion Architecture
```
src/
  domain/         # сущности + интерфейсы репозиториев (чистый TS, без зависимостей)
  application/    # use cases (бизнес-логика)
  infrastructure/ # реализация репозиториев (SQLite), Express роуты, JWT
```

## UI

### Навигация

- **Таббар снизу**: Записи / Аналитика / Настройки
  - Все три таба есть с фазы 1; Аналитика и Настройки до фаз 4 и 5 — заглушки
- **FAB** (кнопка "+") на экране Записей: при тапе раскрывается speed-dial с двумя вариантами — "Одометр" и "Заправка" (иконка + подпись; иконки подобрать при реализации)

### Экран Записей

- **Шапка**: имя автомобиля + "Последняя запись: [дата]" — дата берётся из `measuredAt` первой записи после сортировки; относительные "сегодня/вчера" — в доработках
- **Список**: плоский список всех записей, оба типа вперемешку, сортировка по `measuredAt` убывающая (новые сверху), тай-брейк по `createdAt`
  - Запрос: по `vehicleId` + фильтр `deletedAt === null`; сортировка — чистой `sortEntries` в `entities/entry` (тай-брейк всё равно требует JS, составного индекса нет)
  - Лимита нет: обрезать выдачу без пагинации = молча прятать записи. Пагинация и фильтры — в доработках
  - Строка (`features/entry-item`): карточка `bg-white-100 border-1 border-white-200`, глобальный фон экрана не трогаем
  - Иконка типа: одометр — `bg-blue-100 fill-blue-200`, заправка — `bg-green-100 fill-green-200`
  - Строка значений всегда одна (`whitespace-nowrap` + `truncate` как предохранитель, срабатывать не должен):
    - Odometer entry: "87 210 км"
    - Fuel entry: "87 210 км · 44 л · 1 980 ₽" — одометр первым, чтобы у обоих типов ведущий токен был один и тот же (список сканируется по столбцу пробега); тип читается по цвету иконки
    - Числа — `formatNumber` (`shared/lib/number`), единицы — `text-black-200` тем же кеглем
  - Дата/время под значениями — `formatFullMoment` как есть, с годом: "31 янв. 2021 г., 08:50" (точка и "г." от `Intl`; чистить — при необходимости позже)
  - Стрелок в строке нет, тап по карточке в фазе 1 ничего не делает (редактирование — фаза 5)
  - **Открытый вопрос:** невалидная запись (одометр меньше, чем у предыдущей по `measuredAt`) — помечать её визуально в списке или вообще не давать сохранить? Нужна ли пометка в списке, зависит от ответа
- **Удаление записи**: свайп влево (мягкое, `deletedAt`)
  - Свайп открывает шторку 80px с красной кнопкой "Удалить" (иконка корзины + текст); удаляет только тап по кнопке — двухшаговый жест вместо попапа-подтверждения
  - Компонент действий сразу принимает **массив** действий: "Редактировать" приедет туда же в фазе 5
  - Открыта одна шторка за раз: `openedEntryId` живёт в `widgets/list`, `SwipeActions` управляемый (`isOpen` + `onOpenChange`)
  - Закрывается свайпом вправо и тапом по строке; при скролле — нет (ложные срабатывания на тач-скролле)
  - Жест на `motion` (уже в зависимостях), новых либ не тянем: `dragConstraints { left: -80, right: 0 }`, без эластичности, `dragDirectionLock` против конфликта с вертикальным скроллом
  - Порог открытия: утащили дальше 40px **или** флик со скоростью ~500px/s; иначе пружиной назад
  - Ошибка записи в Dexie сейчас не обрабатывается (не ловим) — до общего механизма ошибок из доработок

### Стаб пустого состояния

- **Глобальный стаб** (нет ни одной записи у машины; дизайн `docs/ui-examples/global-stub.png`):
  - Шапка: имя авто + "Записей пока нет" (без даты последней записи)
  - Карточка по центру: иконка + "Начните вести учёт" + подпись "Записывайте показания одометра и заправки — приложение само посчитает расход и пробег"
  - Две кнопки внутри карточки: "Одометр" / "Заправка" (открывают те же попапы, что и FAB)

### Попап — форма одометра

- Заголовок: "Одометр"
- Поле даты + времени (`measuredAt`): тап открывает попап с календарём и выбором времени, по умолчанию «сейчас», допускает прошлое (бэкдейтинг) — решения в `docs/adr/0004-date-time-picker-on-libraries.md`
- Поле "Показание одометра" (км) — целые, обязательное, > 0, числовая клавиатура на мобиле; невалидное значение блокирует кнопку "Сохранить", текста ошибки нет
- Дельта в реальном времени под полем (относительно соседней по `measuredAt` записи):
  - положительная → зелёная "↑ +260 км с последней записи"
  - отрицательная → красная "↓ −1 350 км — проверьте значение"
  - **Открытый вопрос:** блокировать ли сохранение при отрицательной дельте. Изначально задумывалось сохранять и помечать запись невалидной; альтернатива — не давать сохранить вовсе
- Кнопка "Сохранить"

### Попап — форма заправки

- Заголовок: "Заправка"
- Поле даты + времени (то же, что в форме одометра) — остаётся нейтральным серым, вариантов у контрола нет
- Поля в двух равных колонках: "Одометр" (км) + "Литры" (л) — числовая клавиатура, литры дробные (десятичный разделитель зависит от локали клавиатуры)
- Дельта одометра — аналогично форме одометра
- Поле "Общая стоимость" (₽), во всю ширину
- Все три `Input` — зелёный вариант (`variant="green"`); кнопка "Сохранить" остаётся синей, зелёного варианта у `Button` нет
- Вычисляемое поле в реальном времени: "Цена за литр: 70 ₽" (стоимость ÷ литры)
  - Строка есть в разметке всегда; посчитать нельзя (литры пустые/0/невалидные, стоимость пустая) → "Цена за литр: —", высота попапа не скачет
  - Округление до 2 знаков, хвостовые нули убираются (`70 ₽`, `73,26 ₽`)
  - Форматирование — фасад `shared/lib/number` на `Intl.NumberFormat`, локаль из `i18next.language` (как `shared/lib/date`); прямых вызовов `Intl` в попапе нет
- Кнопка "Сохранить"

Ввод чисел: `Input` строковый, парсинг и нормализация — в форме. Запятая с локализованной клавиатуры остаётся в поле как есть, `,` → `.` только при валидации и сабмите. Литры и стоимость — `/^\d+([.,]\d+)?$/`, длина дробной части не ограничена; одометр — `/^\d+$/`.

### Попап — message

Универсальный попап-сообщение: заголовок + опциональная подпись + кнопка "ОК" по центру. Показывает ошибку.

- Пропы `title` / `description` — готовые строки; про i18n попап не знает
- Закрывается кнопкой "ОК" или тапом по затемнению
- Вызывается через хук `useErrorPopup()` — тексты зашиты внутри хука

### После сохранения

- Во время записи кнопка "Сохранить" заблокирована
- Успех: форма закрывается молча (попапа "Запись сохранена" нет), новая запись появляется в списке с анимацией
- Ошибка записи в IndexedDB: попап message "Не удалось сохранить" / "Попробуйте ещё раз" → закрывает только себя, форма остаётся с введёнными данными, можно повторить
- Сетевые ошибки синхронизации ("Повтор", "Нет сети — запись сохранена локально") — фаза 3
