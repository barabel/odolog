# Собственный механизм bottom sheets вместо vaul

`vaul` удалён: он сам слушает `visualViewport` и двигает шит трансформом, из-за чего экранная клавиатура поднимает шит, но не опускает обратно. Пишем свой механизм: реестр «ключ → компонент» + стек открытых шитов в zustand + визуальная обёртка на `motion`. Ключевой принцип — **не бороться с браузером**: шит прибит `position: fixed; bottom: 0`, никакого JS-репозиционирования под клавиатуру.

## Решения

- **Стек, а не один активный шит.** Состояние — массив фреймов; из шита можно открыть шит. Визуально — плоские слои: один общий оверлей на весь стек, панели по z-index, нижние фреймы остаются смонтированными (стейт форм не теряется), но `aria-hidden` + `pointer-events: none`.
- **Zustand-синглтон.** Провайдера нет, `openSheet`/`closeSheet` — обычные функции, вызываются вне React. Чистая логика стека (push / close-top / close-by-id / remove) вынесена из стора отдельными функциями — она же покрыта тестами, она же делает замену стора однофайловой правкой.
- **Регистрация по ключу, а не передача элемента.** `openSheet('odometer', props)` вместо `openSheet(<Odometer />)`: вызывать шиты будут `widgets/list` и `LayoutIndex`, а прямая передача элемента заставила бы `widgets/list` импортировать `widgets/bottom-sheets` — импорт внутри одного слоя FSD. Ключ развязывает; связь «ключ → компонент» живёт в одном месте и подключается в `app`.
- **Типы через declaration merging.** `shared/lib/bottom-sheet` не может импортировать `widgets`, поэтому карта `SheetRegistryMap` расширяется снизу вверх и хранит **типы пропов**, а не только ключи — рассинхрон «ключ ↔ пропы» ловится компилятором.
- **`AnimatePresence` вместо таймера.** Фрейм удаляется из стека по `onExitComplete`. В старой реализации это был `EXIT_ANIMATION_MS = 550` «с запасом» — связка магического числа с длительностью анимации, главный источник багов.
- **Аппаратная «Назад» закрывает верхний шит.** В вебвью системной кнопки нет — есть только история, поэтому `pushState` на открытие, `popstate` → закрыть верхний, программное закрытие → `history.back()`. Изолировано в `useHistoryDismiss`, стек про историю не знает. Смена роута закрывает весь стек без анимации.
- **Дубли по ключу.** Повторный `openSheet` с ключом, который уже наверху стека, игнорируется (дабл-тап на мобилке — норма, два одинаковых шита — всегда баг). Осознанный дубль — явным `{ allowDuplicate: true }` в месте вызова, а не порогом по времени: временной cooldown даёт и ложные пропуски (медленный дабл-тап), и ложные срабатывания (закрыл → сразу открыл).

## Рассмотренные альтернативы

- **Контекст + `useReducer`** (как было при vaul). Отвергнуто: провайдер, протаскивание реестра пропом в `shared`, ручное разделение на два контекста ради ререндеров, и `openSheet` только через хук. Взамен теряем возможность двух независимых стеков — кейса нет.
- **iOS-style «глубина»** (нижний шит отъезжает и масштабируется). Отвергнуто: `transform` на родителе ломает `position: fixed` у детей и путается с ресайзом под клавиатуру — то есть воюет с главной причиной переезда с vaul.
- **JS-обработка клавиатуры через `visualViewport`.** Отвергнуто: это ровно то, на чём ломался vaul. Если кнопка «Сохранить» окажется под клавиатурой — лечим декларативно, `interactive-widget=resizes-content` в метатеге (на iOS игнорируется).
- **Snap points.** Отвергнуто: обе формы короткие, высота по контенту с `max-height: 90svh` достаточна. Snap points — самая тяжёлая часть vaul, добавляются поверх драга позже, если понадобятся.
- **Свайп только за ручку.** Отвергнуто в пользу нативного Android-поведения: тянется вся панель. Конфликт жестов решается двумя правилами сразу — драг не начинается, если под пальцем скроллируемый контейнер с `scrollTop > 0`, и не начинается внутри `[data-sheet-no-drag]` (барабаны date-picker'а, у которых `scrollTop` в середине по определению).
- **Свой lock скролла фона.** Отвергнуто: `overflow: hidden` на `html` не держит iOS Safari. Берём `react-remove-scroll` (на нём Radix и MUI) декларативно — `enabled={stack.length > 0}`.
- **Термин «drawer».** Отвергнут: в Material Design drawer — боковая панель навигации, нижняя называется **bottom sheet**. Прежнее имя было наследством vaul; переименовываем `widgets/drawers` → `widgets/bottom-sheets`. Функции при этом короткие — `openSheet` / `closeSheet`, они вызываются часто.

## Границы

- Шиты не возвращают результат: контент сам пишет в Dexie, UI подписан живыми запросами. Промис-API (`await openSheet('confirm')`) добавляется поверх, когда появится шит-подтверждение (фаза 5).
- Ленивая загрузка шитов не делается: уникального веса у форм почти нет, а `React.lazy` конфликтует с высотой по контенту (панель выезжает пустой и подпрыгивает). Реестр этому не мешает — обернуть конкретный ключ в `lazy()` можно точечно.
- Обёртка рисует только оверлей, панель, ручку и скроллируемую область. Заголовки, паддинги и кнопки — внутри зарегистрированного компонента.
