# Дата и время — календарь и циферблат на сторонних либах

Ввод `measuredAt` переделывается с самописного колеса (`react-mobile-picker`, 5 колонок day/month/year/hour/minute) на связку **календарь + циферблат**: поле в форме → попап с календарём и строкой времени → модалка с циферблатом. Календарь — `react-day-picker`, циферблат — `timepicker-ui`, обе за собственными обёртками в `shared/ui`.

## Почему не колесо

Пятиколоночное колесо — плотный, непривычный для Android-пользователя контрол: чтобы поставить дату, нужно прокрутить пять независимых лент, и ни одна из них не показывает контекста (какой это день недели, сколько дней в месяце, где «сегодня»). Календарная сетка отвечает на это одним взглядом. `react-mobile-picker` из зависимостей удаляется, `shared/ui/date-picker` удаляется целиком.

## Решения

- **Календарь — `react-day-picker@10`.** Свой писать не стали: сетка, локаль, навигация по месяцам и дропдаун «месяц/год» — это ровно та работа, которую либа делает лучше и уже отладила. Цена — транзитивная `date-fns@4` + `@date-fns/tz`, первая date-либа в проекте.
- **Циферблат — `timepicker-ui@4.4`, и это единственный реальный вариант.** Встраиваемого headless-циферблата не существует: `@mui/x-date-pickers` тянет `@mui/material` + `@emotion/react` (целая чужая дизайн-система и рантайм-CSS-in-JS поверх Tailwind), `react-clock-select` держит React 16 в `dependencies` (мертва), плагин `react-multi-date-picker` — драг стрелок, а не material-тап. `timepicker-ui` — zero runtime deps.
- **Двойное кольцо часов даётся бесплатно и в нужной раскладке.** В 24h-режиме `indexToAngle` считает `index >= 12 ? (index-12)%12*30 : index%12*30`, то есть внешнее кольцо **0-11**, внутреннее **12-23**, оба стартуют сверху. Это не Material-раскладка (там 1-12 / 13-00 с нулём внизу справа) и логичнее её: позиция = час по модулю 12 без исключений.
- **Модалку времени рисует сама либа.** Она вставляется в `document.body` (`position: fixed`, `z-index: 5000/5001` против нашего `z-50`), поэтому нашим попапом не обрезается и лежит поверх. `backdrop: false` убирает второе затемнение, `enableScrollbar: true` отключает её собственный лок скролла — наш `RemoveScroll` уже работает. `ADR 0003` этому не противоречит: там речь про **собственный** механизм модалок, а не про внутренности сторонней либы. Своего попапа `time-picker` в проекте нет.
- **`inline`-режим либы (`inline: { enabled, containerId }`) рассмотрен и отвергнут.** Он встраивает пикер в наш div, но тогда мы выбрасываем её футер (`showButtons: false`) и собираем заново своей кнопкой — а этот футер (два бокса ЧЧ:ММ сверху, иконка клавиатуры слева, кнопка подтверждения справа) и есть нужный нам дизайн.
- **Обе либы темизуются переменными, не классами.** `--rdp-*` (16 шт.) и `--tp-*` (137 шт.) переопределяются нашими токенами в SCSS рядом с обёрткой; `classNames` добавляются адресно там, где переменной не хватило. Полную мапу Tailwind-классов поверх календаря не пишем — это переписывание чужой вёрстки, которое пришлось бы сверять при каждом обновлении.
- **Каждая либа — за собственной точкой входа.** `shared/ui/calendar` над `react-day-picker`, `shared/ui/time-field` над `timepicker-ui`. Вторая обёртка обязательна отдельно: `timepicker-ui` — императивный vanilla-класс (`create()` / события / `destroy()`), единственное место в приложении, где React не владеет DOM; наружу она отдаёт обычный контролируемый компонент. Готовая обёртка `timepicker-ui-react` для этого бесполезна — её `.d.ts` на 26 строк, это `<input>` с прокинутыми `options`.
- **Попап возвращает результат колбэком в пропах.** `openPopup('dateTimePicker', { value, onConfirm })`. Это отменяет запись в границах ADR 0003 «попапы не возвращают результат»: там предполагалось, что контент сам пишет в Dexie, но пикер — переиспользуемый контрол, а не форма, и владеть значением должна форма.
- **Попап поверх попапа — теперь штатный кейс** (форма одометра → `dateTimePicker`). Проверено по коду либы: `popupList.map()` внутри `AnimatePresence`, нижний попап остаётся смонтированным, состояние `react-hook-form` переживает открытие пикера. Известное следствие из ADR 0003 в силе: два оверлея дают сложенное вдвое затемнение.
- **`measuredAt` по умолчанию — текущий момент** с обнулёнными секундами, а не пусто. Основной сценарий — «заправился, записываю сейчас»; пустое поле стоило бы двух попапов ради значения, которое и так «сейчас», и потребовало бы валидации обязательности. Бэкдейтинг остаётся доступен через пикер.
- **Шаг минут — 1, не 5.** Округление до 5 склеивало бы соседние записи в одну отметку времени и переводило их порядок на `createdAt`-тайбрейк, то есть на порядок ввода вместо порядка измерения — а `measuredAt` задаёт таймлайн, по которому считаются пробег и расход (`ADR 0002`). Попадание пальцем в «37» на циферблате компенсируется клавиатурным вводом (`editable: true`).
- **Границы календаря — январь 1900 … декабрь 2100.** Дропдаун месяца/года требует явных `startMonth`/`endMonth`. Диапазон взят заведомо широким, чтобы не подбирать эвристику; следствие — **будущие даты выбираемы**, отдельного запрета нет.
- **Форматирование — `Intl` за фасадом `shared/lib/date`.** `date-fns` приезжает транзитивно, но остаётся деталью реализации `shared/ui/calendar` (единственное, что ей передаётся — объект локали) и по проекту не расползается. Локаль берётся из `i18next.language`, а не хардкодится `'ru'`.

## Рассмотренные альтернативы

- **Свой календарь** (~90 строк: `Intl` для названий месяцев и дней недели + сетка 42 дней). Отвергнуто пользователем: не тот код, который хочется сопровождать ради экономии одной зависимости.
- **Свой циферблат** (~150 строк тригонометрии, два кольца, hit-testing). Отвергнуто после того, как выяснилось, что `timepicker-ui` даёт нарисованный экран целиком, включая клавиатурный ввод, шаги, локализацию и focus-trap.
- **`react-calendar`.** Отвергнут: zero-dep, но self-contained CSS со своей разметкой — стилизация свелась бы к переопределению чужих селекторов, то есть к минусам обоих подходов сразу.
- **Мгновенный коммит выбора в форму** (без «Готово»). Отвергнуто: кнопка «Готово» на макете выглядит как подтверждение, и если она им не является — врёт. Тап по оверлею закрывает попап **без** передачи значения.
- **Отдельная кнопка «Отмена»** рядом с «Готово». Отвергнуто: тап по оверлею её дублирует. У либы времени `cancel` по той же причине прячется, остаётся только подтверждение.

## Границы

- Задача — только пикер. `onSubmit` формы одометра остаётся заглушкой, миграция схемы на единую таблицу `entries` (`ADR 0002`) и форма заправки — отдельные куски.
- Из `shared/ui` в этой задаче появляются: `date-time-input` (поле в форме), `calendar`, `time-field`. Оркестратор — `widgets/popups/date-time-picker`: календарь, строка времени и «Готово», владеет черновиком `Date`.
- Термин `dateTimePicker` — UI-словарь, в `CONTEXT.md` не вносится: там живут понятия предметной области (Vehicle, Entry, Mileage, Consumption), а не названия контролов.
